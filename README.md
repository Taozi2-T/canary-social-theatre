# 金丝雀 · 社交小剧场 1.1.0

一个独立的 SillyTavern 前端扩展。角色每次生成回复后，扩展再调用一次模型，将新的圈内群聊和社交动态显示在这条回复下方。

## 安装

要求 SillyTavern **1.13.2 或更新版本**，不需要酒馆助手、正则脚本、Extras 或额外 Node 包。

### 通过酒馆安装（推荐）

1. 打开酒馆「扩展」→「安装扩展」。
2. 粘贴仓库地址：`https://github.com/Taozi2-T/canary-social-theatre`。
3. 安装完成后刷新网页，在扩展设置里展开「✦ 金丝雀 · 社交小剧场」。
4. 默认调用酒馆当前主 API。确认正文能正常回复后，可点击「生成最新回复」验证。

后续更新可在酒馆「管理扩展」中更新此扩展。本插件不会自动改动你的 API 连接和密钥。

### 离线安装

1. 解压 `canary-social-theatre-v1.1.0.zip`。
2. 将解压得到的整个 `canary-social-theatre` 文件夹放入酒馆的 `data/<你的用户目录>/extensions/`。单用户默认目录通常是 `data/default-user/extensions/`。
3. 检查最终结构是 `data/default-user/extensions/canary-social-theatre/manifest.json`，不要多套一层同名目录。
4. 刷新酒馆网页。在「扩展」设置里展开「✦ 金丝雀 · 社交小剧场」。如果扩展被禁用，在「管理扩展」里启用。
5. 默认为「酒馆当前主 API」并开启自动生成。先确认正文 API 能正常回复，再发送一轮消息。也可点击「生成最新回复」验证安装。

另一种安装位置：`public/scripts/extensions/third-party/canary-social-theatre/`，用于所有用户共用。任选一个位置安装即可，不要安装两份。

ZIP 是离线安装包，不能把本地 ZIP 路径填入酒馆的 Git 仓库安装地址。在线安装使用上面的 GitHub 仓库链接。

## 两种 API 模式

**酒馆当前主 API**：调用酒馆公开的 `SillyTavern.getContext().generateRaw()`，使用你正在连接的主 API、模型和采样预设。小剧场有自己的提示词，传入最近正文、当前角色卡的描述/性格/场景，以及此前小剧场的摘要和人物表。正文完成后排队生成；若此时发起下一轮正文，该正文会等待当前小剧场的主 API 请求完成，避免本扩展同时占用主接口。

**独立 API**：选择此模式并填写地址、模型和 Key。支持 **OpenAI 兼容的 `/chat/completions`**，例如：

```text
https://你的服务商地址/v1
https://你的服务商地址/v1/chat/completions
http://localhost:1234/v1
```

地址必须完整；若服务商有自定义路径，填完整 `/chat/completions` 地址最稳妥。无需鉴权的本地服务可以不填 Key。此模式单独使用设置中的温度和 token 上限，不使用酒馆主 API 的密钥。

独立请求由浏览器直接发送到你填写的服务商，须由端点允许跨域（CORS）；HTTPS 网页也可能阻止直连 HTTP 远端服务。API Key **只在当前页面内存中保留**，刷新后重新填写，不保存进酒馆设置、聊天记录或导出 HTML。独立请求 120 秒后超时，支持重试；暂不支持原生 Anthropic Messages、Gemini 或 Responses 协议。

## 小剧场内容

- 大群：新人、求门路者、学习者、卖课者、下午茶拼单者和已被包养者混杂；有人打听、有人吹嘘、有人拆台。
- 核心小群：固定的高级金丝雀关系网，比较礼物、住房、陪伴、公开程度和社交座次，聊金主的妻子及家族规矩。
- 平台动态：豆瓣、小红书、抖音、微信、推特/X、Instagram，每个勾选的平台每轮生成一条帖子/动态及评论，也可出现私密群聊形式。
- 京圈为主，沪圈和港圈穿插。`{{user}}` 在核心群地位很高，其他人会讨好、试探、借势或用假关心暗讽。
- 前几轮的八卦摘要及群友关系延续，避免每轮完全重置。角色与丑闻均按虚构成年人物创作。
- 不代替你发言、发帖或作决定；群友不能自动知道正文中的私密信息。实际是否遵守这些设定仍取决于模型。

圈内设定可以直接在扩展设置里修改。将你的人设、金主背景、圈内昵称和文风要求写入「补充设定」；支持 `{{user}}`、`{{char}}` 宏。例如：

```text
{{user}}在圈内被叫作晚晚。金主是{{char}}，他在京圈很有话语权。
群聊克制、像真实熟人聊天。少用热梗，不要每轮都晒包。
温梨表面亲近晚晚，实则爱用假关心探口风；宋澄会帮晚晚接话。
正文中没有公开的礼物和行程，不要写成群友已经知道的事实。
```

## HTML 展示与保存

1.1.0 为不同内容提供了独立页面布局：微信群的灰色聊天气泡、豆瓣小组讨论帖、小红书图文笔记、抖音竖屏动态、微信朋友圈、X 时间线、Instagram 照片流。评论区可点击展开/收起，切换频道会进入该平台的独立配色和结构；窄屏下自动调整布局。

展示仅用于虚构社交小剧场，不连接真实社交账号。配图/视频位置以画面描述和抽象背景呈现，并不生成或播放真实图片、视频；点赞和人数是剧情数据，不会替用户执行社交操作。旧版已经保存的场景可直接使用新的界面，无需重新生成。

模型生成结构化的剧情内容（JSON），扩展再将它转换成可切换频道的 HTML 小剧场。这样频道样式一致，也不要求模型每轮重写整套页面代码。所有模型文字按文本转义，不能执行脚本或加载外链资源。

小剧场放在正文下方的独立面板里，有大群、小群与平台按钮，可折叠、重新生成和导出 HTML。HTML 导出包含当轮所有频道，可离线阅读；导出页默认展开所有频道，无需联网。

场景保存在当前聊天的扩展元数据中，不改正文，不新增助手消息。主角色下一轮默认不会自动接收小剧场；小剧场模型会接收自己的前几轮摘要。未自动读取激活世界书、作者注或完整人格描述，需要的重要设定请填写在扩展设置里。

重抽/继续生成正文会为新的文本版本生成新的场景。切回已缓存的版本时显示对应场景；切换旧版本不会额外请求模型。手动修改正文后，可点击「生成 / 重试」生成对应场景。每个聊天保留最近 **300 个版本**；更旧的场景可能需要手动重新生成。

刷新或进入旧聊天只恢复已保存的场景，不自动批量补齐历史消息。关闭「启用每轮自动生成」会同时隐藏面板并停止新任务，重新启用后恢复展示。

## 费用、延迟与故障

每条角色回复默认会额外调用一次模型，使用六个平台时输出较长，建议保留默认 6000 token 上限；具体费用和耗时由所用模型决定。发生失败后不自动无限重试，点击对应面板的重试按钮即可。

「取消待办 / 丢弃本次结果」会取消排队任务，并中止本扩展的独立 API 请求。酒馆公开 `generateRaw()` 没有提供本扩展可独占使用的取消参数，因此主 API 模式下已发送的请求继续等待结束，但结果会被丢弃，服务商仍可能计费。

- **没有设置面板**：确认目录层级和启用状态，检查酒馆版本，刷新网页。
- **长时间等待**：检查主 API 正文是否仍在生成；主模式也可能在等上一个小剧场请求结束。
- **独立 API 连接失败**：检查完整地址、模型名、CORS 和浏览器的混合内容拦截。
- **JSON 不完整 / 缺少平台**：提高输出上限、减少平台或换一个擅长结构化输出的模型。
- **生成风格跑偏**：在补充设定中明确金主背景、称呼、公开程度和聊天风格。

## 验证情况

已对官方 release 分支的扩展接口及事件用法作核对。12 项 Node 自动检查通过，覆盖 JSON 解析、HTML 注入转义、独立请求格式、重复触发、主接口排队、切换聊天、编辑/删除/重抽导致的过期结果丢弃、失败重试、上下文延续、平台结构和新旧配图描述兼容。没有在你的实际酒馆环境或真实收费 API 上做联调，安装后请先点击「生成最新回复」验证。浏览器工具拒绝访问本地 file 页面，因此没有完成浏览器视觉验收。

开发者检查（不影响安装）：

```sh
npm test
```

离线展示：用浏览器打开 `demo/preview.html`。重新生成展示页：

```sh
npm run preview
```
